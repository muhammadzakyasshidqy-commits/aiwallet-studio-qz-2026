Webhook Midtrans tidak mengubah pesanan menjadi PAID? 7 pemeriksaan pertama.

Masalah checkout sering bukan pada QRIS, tetapi pada pemrosesan callback, verifikasi status, idempotensi, atau antrean yang berhenti.

1. Pisahkan status PENDING dan SETTLEMENT

pending berarti pembayaran masih menunggu. Jangan mengirim barang hanya karena halaman checkout selesai. settlement menunjukkan pembayaran telah diselesaikan menurut gateway; untuk kartu, capture perlu diperlakukan sesuai status fraud dan perjanjian merchant.

2. Verifikasi notification signature di server

Tolak notifikasi dengan signature tidak valid. Cocokkan order ID, merchant ID dan nominal terhadap pesanan dalam database. Jangan menerima status pembayaran hanya dari parameter browser atau screenshot.

3. Periksa ulang status lewat API resmi

Jika respons callback hilang atau ambigu, gunakan Get Transaction Status Midtrans dengan kredensial server yang tersimpan secara aman. Jangan pernah mengirim Server Key ke frontend.

4. Jadikan webhook idempoten

Notifikasi dapat tiba berulang. Gunakan kunci unik per event dan proses perubahan status tanpa menggandakan pesanan atau mencatat dua kali pembayaran.

5. Tangani refund dan chargeback

Status PAID bukan akhir dari seluruh siklus. Simpan penanda pembatalan, pengembalian dana dan perselisihan terpisah dari revenue bersih yang telah diterima.

6. Uji timeout serta retry

Server harus menjawab cepat, menjaga keamanan race condition, dan memungkinkan retry. Catat kegagalan dengan trace ID tanpa menyimpan Server Key atau data sensitif.

7. Bedakan uang diterima gateway dan payout bank

Rekonsiliasi transaksi dengan settlement/merchant dashboard serta rekening penerima; keduanya tidak selalu memiliki timestamp yang sama.
