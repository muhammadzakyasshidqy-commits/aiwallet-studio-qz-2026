Yang benar-benar diperiksa

Bukti transfer

  • Chain ID Base 8453 dan alamat token native USDC.
  • Receipt berhasil, hash transaksi dan block hash.
  • ERC-20 Transfer event ke penerima tepat, filter pengirim opsional.
  • Nominal USDC exact 6 desimal; tanpa floating-point.

Kesalahan dan ketidakpastian

  • RPC host harus berbeda; ketidaksesuaian bukti ditolak.
  • Minimum konfirmasi dapat diatur.
  • Event lain seperti Approval diabaikan tanpa menghilangkan Transfer.
  • RPC tidak tersedia, status pending dan jumlah kurang → tidak diverifikasi.

Pengujian yang dapat diaudit

Rilis 1.1 menjalankan 46 tes offline, termasuk skenario lawan untuk response RPC rusak, redirect, perbedaan block hash, nominal melampaui uint256, network error, dan pembayaran salah penerima. Batas kemampuan yang jelas

Receipt Guard bukan checkout, alat anti-penipuan menyeluruh, dompet, pembayaran fiat, pembuktian order ID, atau verifikasi tanda tangan EIP-3009. Untuk sistem produksi, developer tetap harus menyimpan pemetaan order→tx hash yang unik, mencegah pengkreditan ganda, menerapkan finality policy, dan merekonsiliasi pembayaran secara terpisah.

Lisensi distribusi, dukungan integrasi, dan harga final disepakati berdasarkan kebutuhan. Source code hanya diberikan sesuai lisensi setelah perjanjian, tidak diunduh bebas dari halaman ini.
